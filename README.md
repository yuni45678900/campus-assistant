# 校园智能小助手 · Campus Assistant

> 写材料 / 二次开发前先读 [`PROJECT_BRIEF.md`](./PROJECT_BRIEF.md)：项目定位、模块职责与边界、
> 业务流程、技术约束、命名规范，以及**写材料时的术语表与禁止说法**。

基于 **本地 Qwen3-8B** + **混合检索 RAG** 的校园问答系统。把学校简介、专业介绍、
食堂介绍等 Word 资料交给它，就能用自然语言提问，答案**全部来自你的资料并标注出处**，
不需要联网，也不会上传任何数据。

```
                ┌──────────────────── 离线运行，数据不出本机 ────────────────────┐
提问 ──► 查询改写 ──► 向量检索 ┐
                              ├─► RRF 融合 ─► 重排 ─► 拼 Prompt ─► Qwen3-8B ──► 流式回答
        └────────► BM25 检索 ─┘                                        (Ollama)
                              └──────────► 引用来源卡片 ◄──────────────────────┘
```

---

## 一、它和"直接问 ChatGPT"有什么不同

| | 直接问通用大模型 | 本系统 |
|---|---|---|
| 校园专属信息 | 完全不知道，会编造 | 从你的文档里检索后回答 |
| 数据安全 | 需上传到云端 | 全本地，不联网 |
| 答案可追溯 | 无 | 每条回答附来源文件与章节 |
| 资料更新 | 无法更新 | 换文档 → 重建索引即可 |

**核心技术点是"先查后答"**：8B 模型的能力瓶颈在于记不住校园细节，而 RAG 把
"记忆"交给检索，模型只负责把检索到的资料组织成人话。这也是本系统能明确回答
"第三食堂周五中午几点暂停服务"这类问题的原因。

## 二、环境要求

| 项目 | 要求 | 你的机器 |
|---|---|---|
| 操作系统 | Windows 10/11 / macOS / Linux | Windows ✔ |
| 内存 | ≥ 16 GB（8B 模型 Q4 量化约占 6 GB） | 32 GB ✔ |
| 磁盘 | ≥ 15 GB 空闲 | 需确认 |
| 显卡 | **可选**：有 N 卡时 Ollama 自动把模型载入显存加速；无独显可纯 CPU 运行 | RTX 4060 8 GB ✔ |
| Python | 3.10 ~ 3.13 | — |

> **纯 CPU 模式性能预期（16 线程 / 32 GB 内存、关闭显卡加速的实测值）**：
> 生成速度约 **15 token/s**（比预估的 5~8 快一倍），
> **首字响应 16~32 秒**（瓶颈在 prompt 处理），一条完整回答 **17~35 秒**。
> 系统已针对 CPU 做了专项优化（见第五节），前端全程流式输出 + 阶段状态提示，
> 不会让人以为卡死。
>
> 想再快一点：把 `RERANK_TOP_N` 从 4 调到 3（省约 4 秒），
> 或换 `CAMPUS_LLM_MODEL=qwen3:4b`（速度翻倍，质量略降）。

## 三、快速开始

### 步骤 1 · 安装 Ollama（模型运行时）

> ⚠️ **注意**：ollama.com 官网的下载按钮会 307 跳转到 **github.com**。
> 在部分校园网 / 企业网环境下 GitHub 不通，点官网下载会卡住或失败。
> 下面三个通道任选其一（均已实测）。

**通道 A：GitHub 直链**（能访问 GitHub 时用这个）

```
https://github.com/ollama/ollama/releases/download/v0.34.2/OllamaSetup.exe
```

Release 列表页（可查看全部版本）：<https://github.com/ollama/ollama/releases>

**通道 B：国内加速镜像**（GitHub 不通时用这个，实测可用）

```
https://ghproxy.net/https://github.com/ollama/ollama/releases/download/v0.34.2/OllamaSetup.exe
```

用法就是在原始 GitHub 链接前面拼上 `https://ghproxy.net/` 前缀。
备选前缀：`https://gh-proxy.com/`。

**通道 C：包管理器**（装了 winget 的话最省事）

```powershell
winget install Ollama.Ollama
```

**安装包信息**（用于校验下载是否完整）

| 项目 | 值 |
|---|---|
| 文件名 | `OllamaSetup.exe` |
| 版本 | v0.34.2 |
| 大小 | **1,569,993,232 字节（约 1.57 GB）** |

下完在资源管理器里看一眼大小对不对，能避免装上一个损坏的安装包。

安装过程就是双击 → 一路下一步，会自动加入 PATH 并注册后台服务（监听 11434）。

**装完必须新开一个终端窗口**，旧窗口读不到新的 PATH：

```bash
ollama --version          # 应输出 ollama version 0.34.2
```

**然后拉取模型**（约 5.2 GB，Q4_K_M 量化版）：

```bash
ollama pull qwen3:8b
```

`ollama pull` 支持断点续传——中断了直接重新执行同一条命令即可。
`registry.ollama.ai` 在国内实测可直连，一般能拉下来，只是速度看网络。

> 如果模型实在拉不动，可用 ModelScope 下载 GGUF 后本地导入：
> ```bash
> # 从 modelscope.cn 搜索 Qwen3-8B-GGUF，下载 Q4_K_M 那个文件，然后：
> ollama create qwen3:8b -f Modelfile   # Modelfile 里写：FROM ./Qwen3-8B-Q4_K_M.gguf
> ```

**验证模型可用**：

```bash
ollama list               # 应看到 qwen3:8b，SIZE 不为 0
ollama run qwen3:8b "你好" # 能正常回话即可，退出用 /bye
```

> 若 `ollama list` 里 SIZE 显示 0 B，说明模型文件损坏，
> 执行 `ollama rm qwen3:8b` 后重新 pull。

### 步骤 2 · 安装 Python 依赖

双击 `setup.bat`（会创建 `.venv` 并安装依赖，torch 约 2 GB）。

或手动：

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 步骤 3 · 放入校园文档

把 `.docx` / `.pdf` / `.txt` / `.md` 放进 `data/raw/`，支持子目录。

> 想先跑通流程看看效果？执行 `python tools/make_sample_docs.py`
> 会生成 3 份虚构的演示文档（明德大学）。

### 步骤 4 · 环境体检（强烈建议）

```bash
python -m app.cli doctor
```

会逐项检查依赖、文档、索引、Ollama 与模型，缺什么直接告诉你。

### 步骤 5 · 构建索引

双击 `build.bat`，或：

```bash
python -m app.cli build
```

首次运行会自动下载嵌入模型（bge-small-zh，约 95 MB）和重排模型（约 1.1 GB），
走 hf-mirror.com 国内镜像。

### 步骤 6 · 启动

双击 `start.bat`，浏览器打开 **<http://127.0.0.1:8000>**。

## 五、页面与角色分工

| 页面 | 地址 | 给谁用 | 有什么 |
|---|---|---|---|
| 入口门户 | `/` | 所有人（公开） | 校园插画场景、两张角色卡、登录入口、登录后显示身份与退出、服务与索引实时状态 |
| 学生端 | `/student` | 学生账号 / 管理账号 | **统一走自动路由**：直接提问，系统自己在全部资料里找答案并给出处（**需登录**） |
| 定向页 | `/student/<分类名>` | 管理账号（调试用） | 锁定单个分类检索，不串味；主入口不再暴露它 |
| 管理端 | `/admin` | 仅管理账号 | 知识库运维控制台（**需登录**，学生账号进不来） |

分类是**按 `data/raw/` 动态发现**的，没有硬编码 —— 上传文档时系统自动归类、自动建目录，
所以这里不列固定清单。前端为主题色留了兜底：文件名命中内置配色就用那一套，
没命中就按顺序分配一套（所以任何新分类都有像样的外观，不会掉成黑白）。

学生端刻意保持极简：**不列分类、不摆宫格**。学生只管提问，
"资料被分成了几类"是管理端的事 —— 问什么都能自动找到对应的那份资料。

### 管理端六个视图

> 术语：代码里管它叫 assistant，界面上叫**分类** —— 就是 `data/raw/` 下的一个文件夹。
> 用户不需要关心它，上传时自己归类。

| 视图 | 做什么 |
|---|---|
| 概览 | 统计卡（含今日提问 / 没答出来）+ 知识库分布条形图 + 「需要注意」的问题文件提示 |
| 知识库 | 按分类展开文档表，逐份删除、单独重建索引、删掉整个分类 |
| 上传文档 | **拖进去就行**，系统读内容自动归类（见下） |
| 问答记录 | 学生端每次都留一条：谁问的、问什么、答什么、命中哪些资料（**超管看全部，学校管理员只看本校**，见下） |
| 学生账号 | **开号**：学校 + 账号 + 密码，开完交给学生登录（侧栏叫「🔑 学校账号」）|
| 系统状态 | 运行参数、**校园地图设置**、回收站、危险操作 |

#### 问答记录：学生问过什么，后台都看得见

学生端每问一轮，服务端就往 `data/logs/qa.jsonl` **追加一条** —— 谁问的、什么时候、
问题、完整回答、耗时、命中了哪几份资料、有没有答不出来。管理端这一页把倒序列出来：

| 能力 | 说明 |
|---|---|
| 可见范围 | **超级管理员看全部；学校管理员只看本校**（列表 / 统计 / 搜索 / 导出 / 清空，全部按校隔离） |
| 筛选 | 按助手筛、关键词搜（问题 / 回答 / 账号 / 学校都能搜）、只看「没答出来」的 |
| 展开 | 点一条展开看完整回答与命中的资料文件名 |
| 导出 | 一键导出 CSV（带 BOM，Excel 双击不乱码）。学校管理员导出的文件名带校名 |
| 清空 | 演示前想从零开始。学校管理员点「清空」**只清本校**，兄弟学校的记录原样留着 |

几条设计上的取舍：

- **按学校隔离在数据层做，不在前端藏**：`_record_scope()` 在服务端把范围算成
  「不限 / 某个学校」，再传给 `records.query(..., school=...)`。前端只是照着显示
  「本校 N 条」；就算绕过页面直接打接口，学校管理员也拿不到别校的记录。
  判定规则：超管与 `CAMPUS_ADMIN_TOKEN` 旁路口令 = 全部，其余管理身份 = 自己的 school。
- **划分依据是记录里的 `school` 快照**，不是实时查账号表：学生换了学校、账号被删，
  历史记录仍归当时那所学校，统计不会跟着漂。

- **用 jsonl 不用数据库**：这是个要打包分发、双击就跑的系统，多一个 sqlite 就多一层
  依赖和迁移麻烦。一行一条，记事本也能看，坏一行只丢一行。
- **写记录绝不影响问答**：记录里任何异常都吞掉，不影响学生拿到答案；单文件超过 8 MB
  会自动只保留最近 4000 条，长期开着也不会把磁盘写满。
- **只记管理端能看的东西**：不含密码等敏感信息；学生账号读这个接口会被 403 挡回去。
- **记录入口在学生端统一收口**：不额外多跑一遍链路，正则在 SSE 流里顺手把
  delta / sources / done 攒下来，流结束（含中途关页面）时统一落盘。

#### 上传：拖文件，或者直接拖一个文件夹

上传时**不用选目标**，两种走法：

| 你怎么传 | 系统怎么归类 |
|---|---|
| **拖整个文件夹**（或点「📁 选择整个文件夹」） | **顶层文件夹名就是分类名** —— 你在电脑上怎么分的，传上去就怎么落，不劳模型 |
| **拖零散文件**（或点「📄 选择文件」） | 读正文开头约 1200 字，让本地 qwen3 判断该归哪一类 |

零散文件的判定细节：

1. 先落到 `data/incoming/` 暂存（**在 `data/raw` 之外**，免得凭空多出一个分类）；
2. 解析正文开头约 1200 字，连同文件名交给模型：
   - **优先复用已有分类**（「专业设置」会归进已有的「招生」）；
   - 确实不相干才新建（「快递地址」→ 新建「后勤服务」）；
3. 把文件搬进 `data/raw/<分类>/`，删掉暂存；
4. 自动重建该分类的索引 —— 传完就能问，不用再点一次"重建索引"。

判定依据会显示在上传结果里（`folder: 按文件夹名归入「招生」` /
`model: 内容符合已有分类「后勤服务」`），不会让文件被黑盒默默归档。
模型不可用时逐级降级：文件名命中已有分类 → 用文件名当分类名，所以**上传永远不会因为模型出问题而失败**。

> 拖文件夹时会自动跳过不支持的文件（照片、压缩包、快捷方式等），不会刷一屏红字。
> 文件名重复时按同名覆盖处理，并会在结果里标出来。

#### 校园地图入口（可选）

「系统状态 → 校园地图」里填上网址、打开开关，学生端**左上角品牌名右侧**就会出现一个 📍 图标，
点开新窗口打开地图页。不填 / 关掉，学生端一切照旧，什么都不显示。

| 项 | 说明 |
|---|---|
| 地图地址 | 只收 `http://` / `https://` —— 它是当链接用的，`javascript:` 之类一律拒收 |
| 入口名称 | 鼠标悬停时的提示文字，默认「校园地图」 |
| 开关 | 关掉学生端就不显示；开着却没填地址也会自动落回关闭（免得点不动） |

配置存在 `data/settings.json`，学生端通过**公开**接口 `GET /api/site` 读它 ——
未开启时这个接口不会吐出任何地址，不会泄露半截配置。写入则只有管理身份能做。

### 登录与账号体系

三类身份，权限是**包含**关系而不是平行关系：

```
超级管理员（.env 里的 admin）   管理端 + 学生端 + 开号
学校管理员（管理端开出来的号）   管理端 + 学生端
学生      （管理端开出来的号）   只有学生端
```

```
        ┌──────────────── 管理端 /admin ────────────────┐
        │                     ▲                        │
   管理身份                    │ 任何登录身份             │ 管理身份
        │                     │                        ▼
        └──────────────▶ 学生端 /student ──────▶ 门户 / （登录入口，公开）
```

#### 管理端现场开号（演示主流程）

管理端侧栏「🔑 学校账号」里填三个东西就能开号：

| 填什么 | 说明 |
|---|---|
| 学校 / 大学 | 学生端侧栏会显示这个校名 —— 演示时一眼看出是给哪个大学开的号。**建议用「A大学」这类泛化名称，别用真实校名** |
| 账号 / 密码 | 交给学生，他在门户登录即可。账号 3~24 位字母数字 |
| 身份 | `学生`（只进学生端）或 `学校管理员`（两端都能进） |

开完立刻生效，不用重启服务。把「学校 + 账号 + 密码」发给学生就行。
账号存在 `data/accounts.json`，密码明文存放 —— 演示够用且好排查（忘了密码直接打开看），
真上生产应当换成哈希 + 数据库。

#### 内置凭据（`CAMPUS_*`，写在 `.env`，改完重启生效）

| 账号 | 密码 | 能进哪里 |
|---|---|---|
| `admin` | `admin11` | 管理端 + 学生端（超级管理员，一直在） |
| `student` | `student11` | 只有学生端（内置演示号，学校名取 `CAMPUS_STUDENT_SCHOOL`） |

动态账号和内置账号互不影响：开出来的号存在 JSON 表里，删掉也不影响 `admin` 登录。

#### 三条硬约束，都有测试兜着

- **未登录**：`/student` 和 `/admin` 都被 302 回门户，带上 `?locked=<角色>`；
  门户据此自动弹出对应的登录框，并说明原因。`/api/assistants`、`/api/chat` 直接 401。
- **学生账号进管理端**：页面 302 → `/?locked=admin`；接口返回 **403**
  「当前是学生账号，无权访问管理端」；就算拿学生账号去登管理端，登录接口也会 403 拒绝。
- **管理身份进学生端**：畅通无阻。管理端侧栏那个「← 回到学生端」永远有效，
  方向上只有学生→管理这一侧是封死的。

会话不做服务端存储：Cookie 值是 `角色.base64(账号).签发时间戳.HMAC签名`，
密钥由账号密码派生。手改 Cookie 把 `student` 改成 `super` 是没用的 —— 签名立刻对不上
（默认 8 小时过期）。**每次请求都会回查一次账号表**，所以管理端改了某人的学校名、
或者把账号删了，已登录的会话下一次请求就立刻反映出来（删号即下线）。

三道防线各管一段，互为补充而不是二选一：

| 层 | 位置 | 管什么 |
|---|---|---|
| 页面门禁 | `GET /student`、`GET /admin` | 未登录/越权直接 302 回门户 |
| 前端门禁 | `student.html` / `admin.html` 启动时 | 堵住 `/web/*.html` 这类绕行入口 |
| 接口校验 | `/api/assistants`、`/api/chat`、全部 `/api/admin/*` | 真正的数据安全 |

界面上：学生端侧栏显示「校名 · 姓名」身份条，只有管理身份才看得到「进入管理端」；
管理端右上角是身份标 + 「退出」；**门户顶栏**登录后也会出现「身份 + 退出」胶囊，
未登录时整块隐藏 —— 不用再绕进学生端/管理端才能退出。
**知识库为空时两端都是空的** ——
学生端会提示「知识库还是空的，等管理员上传资料后就能提问了」，而不是报错。

### 安全约定

上传与删除都在 `app/admin.py` 里统一收口，路由层只做参数转发：

- **名称收敛**：助手名 / 文件名一律压成单层名称，丢掉 `../`、`/`、`\` 与非法字符；
- **路径二次校验**：落盘前确认目标确实在 `data/raw/` 之下；
- **软删除**：删除一律移入 `data/trash/<时间戳>/`，不做真删，可人工还原；
- **单文件上限** 1024 MB（`CAMPUS_MAX_UPLOAD_MB` 可调）；
- **问答记录只进不出**：写入由服务端统一收口，只记问题/回答/命中资料，
  不含密码等凭据；读 / 导出 / 清空三个接口都只认管理身份，学生账号访问直接 403；
- **账号登录**（`.env` 里的两套账号）：学生账号只能进学生端，管理账号两端都能进；
  会话是 HMAC 签名的 Cookie（默认 8 小时），改不了也伪造不了。
  另有一个 `CAMPUS_ADMIN_TOKEN` 旁路口令，给脚本/第三方调用用，留空即关闭；

> 上传有两条通道，互为兜底：标准 `multipart`，以及**零依赖**的裸流通道
> `POST /api/admin/upload/raw`。服务端没装 `python-multipart` 时页面会自动降级到后者 ——
> 否则 FastAPI 会在「定义路由」阶段就抛错，整个服务都起不来。

### 静态展示版（可选，需自行生成）

仓库**不含**静态展示站。如需一个"打开就能看"的纯静态展示页（给老师同学预览、或交材料），
按下面三步自行生成（产物在本地，不会随代码仓库发布）：

```bash
.venv\Scripts\python.exe tools\gen_presets.py    # ① 用本机模型真实跑一遍预置问答，生成 qa.json 快照
.venv\Scripts\python.exe tools\build_demo.py     # ② 抓接口快照 + 内联成 assets/data.js + 派生各分类独立页
.venv\Scripts\python.exe tools\pack_demo.py      # ③ 打包成 zip（入口 index.html 在压缩包根目录）
```

生成物是纯静态、零外部依赖的站点，可导入资料库发布、拿到一个永久链接。
它的能力有边界：**访客不能自由提问**（只能点预置问题）、管理端是**只读快照**、
数据不会自动更新（改完文档要重跑 ①②③）—— 自由提问需要本机把 qwen3:8b 跑起来，
云端静态托管跑不动这个模型，所以想现场随便问就用本机完整版（`start.bat`）。

调试小开关：任意学生端页面加 `?ask=1` 会自动展开第 1 条预置问答，`&speed=0` 关掉打字动画
（自动化截图/DOM 校验用）。

## 六、为 CPU 做的专项优化

纯 CPU 跑 8B 模型，最大的问题不是"跑不动"而是"慢得让人放弃"。以下优化都已在代码中生效：

| 优化项 | 做法 | 效果 |
|---|---|---|
| **关闭思考链** | Qwen3 默认先输出一大段思考过程，本系统通过 `think=false` + `/no_think` 双重关闭 | 首字延迟**减半** |
| 收紧上下文 | `num_ctx` 压到 3072，只喂 Top-4 片段（约 1200 token） | prompt 处理从 40s 降到 10~20s |
| 限制输出 | `num_predict=512`，提示词约束回答 ≤300 字 | 避免生成上千 token 干等 |
| 模型常驻内存 | 启动脚本设 `OLLAMA_KEEP_ALIVE=-1` | 省掉每次 10~30 秒的模型加载 |
| 单并发 | `OLLAMA_NUM_PARALLEL=1` | 防止并发请求撑爆内存 |
| 异步不阻塞 | 检索等 CPU 密集操作走 `asyncio.to_thread` | 生成时可随时中断 |
| 流式 + 状态提示 | SSE 逐字返回，前端显示"检索中/生成中" | 主观等待感大幅降低 |
| 查询改写不调模型 | 多轮追问用规则补全而非 LLM 改写 | 省掉一次 10 秒的往返 |

**嫌慢怎么办？** 改 `config.py` 或设环境变量换小模型：

```bash
set CAMPUS_LLM_MODEL=qwen3:4b      # 速度翻倍，质量略降
ollama pull qwen3:4b
```

## 九、常见问题

**Q：回答"没有找到相关信息"，但资料里明明有？**
先跑 `python -m app.cli search "你的问题"` 看检索结果。
- 检索没命中 → 文档可能没解析成功（表格/扫描件），跑 `doctor` 看文档清单
- 检索命中但模型没答 → 句子太长被切断，调大 `CHUNK_SIZE` 到 600 试试

**Q：下载模型时报 `Expecting value: line 1 column 1 (char 0)`？**
这是国内 + Windows 组合下的经典坑，有两个成因，本项目都已处理：

1. **Xet 传输协议**：新版 `huggingface_hub` 默认走 Xet，而 hf-mirror.com 不支持，
   返回非 JSON 内容。已在 `config.py` 与 .bat 中预设 `HF_HUB_DISABLE_XET=1`。
2. **符号链接与缓存复用**：`huggingface_hub` 默认把文件放在全局缓存里，再用符号链接
   映射到使用目录。Windows 上若链接创建受限、或复用了上次中断留下的空缓存文件，
   就会得到一批 **0 字节的 config.json / modules.json**，报的正是这个 JSON 错。

为此本项目**不使用 huggingface_hub 的缓存机制**，而是由 `app/models.py` 直接向镜像站
请求文件清单并下载到 `data/models/`，下载后逐个校验，发现空文件自动重新拉取。
所以即使中途断网，重跑一次 `build.bat` 就能自愈。

**Q：`data/models/` 占多大空间？**
约 1.3 GB（嵌入模型 95 MB + 重排模型 1.1 GB）。不需要重排的话，在 `config.py`
里设 `ENABLE_RERANK = False`，可省下这 1.1 GB。

**Q：完全没有网络，能离线部署吗？**
可以。把整个项目目录（含 `data/models/`）拷到目标机器即可，模型无需重新下载；
Ollama 的模型目录（默认 `C:\Users\<你>\.ollama\models`）同样直接拷贝，
或用 `ollama create` 从 GGUF 文件本地导入。

**Q：扫描版 PDF 读不出来？**
本项目不支持 OCR。请先用工具转成文字版 PDF，或复制内容到 Word 再入库。

**Q：.doc 老格式怎么办？**
解析器（python-docx）只认 `.docx`，遇到 `.doc` 是**直接抛错**的。系统按
"**当场拒收，不做误导**"处理：

- 上传 `.doc` 会被拒绝，并明确提示「请用 Word 另存为 .docx」；
- 已经躺在 `data/raw/` 里的 `.doc` 不会消失，管理端的「概览 → 需要注意」和
  「知识库」里都会标成 `⚠ 老版 .doc，无法解析`，也解释了"文档数 > 入库数"的差额。

**Q：账号密码是什么？怎么改？**
- **内置账号**写在 `.env` 里：`admin` / `admin11`（超级管理员，管理端 + 学生端），
  `student` / `student11`（只有学生端）。改完**重启服务**生效。
  别把 `.env` 提交到仓库（已在 `.gitignore` 里）。
- **给学生用的账号**在管理端「🔑 学校账号」里现场开，开完立即生效、不用重启，
  存在 `data/accounts.json`。删号后该账号已登录的会话下一次请求就失效。

**Q：演示时怎么走一遍？**
1. 管理端登录（`admin` / `admin11`）→ 侧栏「🔑 学校账号」→ 填学校名 + 账号 + 密码 → 创建
2. 侧栏「⬆️ 上传文档」把资料传进去 → 需要时点重建索引
3. 门户 `http://127.0.0.1:8000` → 点「学生端」→ 用刚开的号登录
4. 学生端侧栏显示「校名 · 姓名」，问什么答什么，来源可追溯

没传文档的话两端都是空的 —— 学生端会提示「知识库还是空的，等管理员上传资料后就能提问了」。

**Q：被弹回门户了 / 提示"无权访问管理端"？**
- 没登录：`/student` 和 `/admin` 都会 302 回门户，门户自动弹出对应的登录框。
- 用学生账号点管理端：会提示「当前是学生账号，进不了管理端」，换管理员账号登录即可。
- 登录超过 8 小时：会话过期，重新登录一次即可（`CAMPUS_SESSION_HOURS` 可调）。

**Q：索引重建要多久？**
每 1000 个片段约 30~60 秒（CPU）。日常新增文档可增量重建，直接覆盖。

**Q：模型回答一半被打断？**
CPU 生成较慢，若超过 300 秒会超时。调小 `CAMPUS_LLM_MAX_TOKENS`，
或提高 `REQUEST_TIMEOUT`。

**Q：想换成别的模型？**
Ollama 支持的所有模型都能换：`set CAMPUS_LLM_MODEL=qwen2.5:7b`。
注意非 Qwen3 模型没有思考链，`LLM_THINK` 设置无影响。
